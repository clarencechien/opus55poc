# Pilot 結果：hard 情境（S1、S3）

日期：2026-11-18。Opus 5.5（effort high，Claude Code 子代理）對 Qwen 3.8 Flash（OpenRouter，`reasoning.effort = high`）。

## hard 情境的內容

平面圖在 `inputs/hard/plan.png`；答案卷由秘密 seed 產生，不放進 git。

- **L 形資料機房：** 東北角挖掉一間 UPS 室，機房多邊形有 6 個頂點，UPS 室與機房之間的內牆上有一扇門 D2。
- **5 根獨立柱：** 其中一根落在 C 列的機櫃帶上，那一格空出來，編號也跳過（C05 → C07）。
- **混合櫃寬：** B 列前 3 櫃是 800 mm 的 GPU 櫃，其餘 600 mm，兩列總長相同。
- **轉向的列：** 西北區的 E、F 兩列南北走向，分別朝東、朝西。
- **規模：** 3 條冷通道、3 台 CRAH（兩台在西牆、一台在東牆），共 58 櫃。
- **尺寸標註：** 每組機櫃列都有尺寸鏈，標出起點、寬度變化和空格。

## 解讀

1. **在這種「有尺寸鏈的工程圖 → 精確座標 → Blender 腳本」任務上，兩個模型都已經到天花板。** 連輕量的 Qwen Flash 都能把 58 櫃的 L 形機房做到每櫃 0 mm 誤差。Qwen 這次還自己寫 Blender Python，去分析平面圖的像素，找出機櫃前緣的三角符號。
2. **能量到的差距只剩效率：** 在 hard 上，Opus 的用時是 Qwen 的 1/15（S1）和 1/3.5（S3），呼叫次數是 1/8 和 1/2.5。時間幾乎全是模型回應時間。
3. **要測出空間能力的差異，題目要改成「沒有標準答案可以直接換算」的形式：**
   - 只有比例尺、沒有尺寸鏈的圖，或是手繪、掃描歪斜的圖，要模型自己量；
   - 照片 → 機房佈局（從透視照片推回平面位置）；
   - 只給模糊的文字需求，例如「放 60 櫃、兩組冷通道、避開柱子、留維修空間」，由模型自己規劃佈局，再用規則檢查；
   - S2 這類外觀題的人工盲測；
   - S4：Web3D 互動、面板錨定。
